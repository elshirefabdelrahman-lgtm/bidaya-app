# Bidaya — إدارة المركز والحسابات

واجهة عربية RTL تحافظ على هوية المركز. التشغيل الفعلي يستخدم Supabase فقط؛ لا توجد أزرار Demo أو دخول تجريبي في التطبيق، ولا تُحفظ البيانات المالية في LocalStorage. بيانات الاختبار موجودة في الاختبارات فقط.

## التشغيل المحلي

يتطلب Node.js 24 وMicrosoft Edge لاختبارات الواجهة.

```powershell
cd D:\bidaya.app
npm ci
npm start
```

افتح http://localhost:4174 وسجّل الدخول بحساب المركز. لا توجد استضافة Web عامة ضمن نطاق التسليم الحالي.

## الحالات والتحصيل

أدخل المبلغ المتفق عليه بالكامل عند إنشاء الحالة. تُفتح تفاصيلها بعد الحفظ؛ اضغط «تسجيل دفعة» لأي مبلغ جزئي أو كامل. المدفوع هو مجموع الدفعات غير الملغاة، والمتبقي = التعاقد − المدفوع. الدفعة نفسها تظهر في التحصيلات والتقارير؛ لا تُدخلها مرتين. التصحيح بإلغاء موثّق ثم تسجيل بديل، مع الاحتفاظ بالأصل وسجل التدقيق.

## التحقق والبناء

```powershell
npm test
npm run check
# شغّل npm start في نافذة أخرى:
npm run test:case-payments
npm run test:ui
npm run test:supabase-ui
npm run build
npx cap sync android
```

مجلد dist يحتوي ملفات Web العامة المجمّعة فقط. اختبارات الواجهة تعترض الاتصالات وتستخدم بيانات مصطنعة؛ ليست اختبارات حفظ سحابي. اختبارات SQL المحلية تعمل في PostgreSQL معزول عبر PGlite.

## Android

المعرّف com.bidaya.center. يتطلب Java 21 وAndroid SDK 36 وBuild Tools 36.0.0. اضبط JAVA_HOME وANDROID_HOME وGRADLE_USER_HOME إلى المسارات المناسبة، ثم أنشئ android/local.properties الذي يحتوي sdk.dir بمسار SDK. هذا الملف غير مرفوع إلى Git.

```powershell
.\android\gradlew.bat -p android :app:assembleRelease --no-daemon --max-workers=1
node scripts/sign-android.mjs
```

التوقيع يستخدم مفتاح PKCS12 مشفّر خارج المشروع، افتراضيًا D:/bidaya-tools/signing/bidaya-release.p12 (يمكن تخصيصه بـ BIDAYA_KEYSTORE). كلمة مروره محفوظة في مخزن بيانات اعتماد نظام التشغيل باسم الخدمة Bidaya Android release والحساب com.bidaya.center، ولا تُطبع. احتفظ بنسخة احتياطية مؤمّنة من المفتاح وبيانات اعتماده قبل نقل جهاز البناء؛ فقدهما يمنع تحديث النسخة المثبّتة بنفس التوقيع. لا ترفع المفتاح أو كلمات المرور إلى Git.

التحديثات: عدّل الكود، شغّل الاختبارات، ثم build وcap sync، وزد versionCode وversionName في android/app/build.gradle، وابنِ ووقّع بالمفتاح نفسه. جُهّز OtaKit للنسخة 1.1.0؛ راجع docs/OTAKIT.md لحالة الربط والنشر وحدود الاختبار. تغييرات Native تتطلب APK جديدًا.

## الاتصال والأمان

src/config.js يحتوي URL وPublishable Key عامين فقط. Auth عبر login، وإدارة الحسابات عبر admin-users؛ القراءة app_snapshot والحفظ app_command. الجلسة في الذاكرة وتجديدها متسلسل. عند غياب الإنترنت يظهر خطأ ولا يُحفظ بديل محلي. تُحمّل البيانات بعد الدخول والتنقل والتحديث؛ لا يوجد Realtime. تسجيل الدخول من جهاز آخر يعيد جلب البيانات المركزية وفق الصلاحيات.

طُبقت 001–006 سابقًا، ثم 007 لإصلاح صلاحية قراءة profiles لحساب الخدمة وصلاحية إدراج سجل إعادة تعيين كلمة المرور. لا تعِد تشغيل migrations القديمة على المشروع الحالي. لا يوجد Service Role Key في الواجهة.

CORS يسمح بعنوان الاختبار http://localhost:4174 وعنوان Android https://localhost. التسجيل العام للحسابات مُعطّل؛ الإنشاء من إدارة الحسابات فقط. روابط استعادة كلمة المرور تشير حاليًا إلى الكمبيوتر المحلي http://localhost:4174/؛ يلزم فتحها على الكمبيوتر والخادم يعمل، وليست رابطًا متاحًا من هاتف بعيد.

راجع docs/DELIVERY.md لحالة التحقق وحدوده. التقارير الأقدم في docs توثيق تاريخي وتُقدَّم عليها هذه الحالة.
