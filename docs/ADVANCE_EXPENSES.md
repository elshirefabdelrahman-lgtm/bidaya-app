# عرض السلف في المصروفات

صفحة المصروفات تعرض المصروفات الأصلية والسلف المصروفة ورد السلف النقدي من بيانات app_snapshot نفسها، دون إدراج صفوف إضافية في expenses أو تعديل قاعدة البيانات.

- السلفة: تصنيف «سلفة موظف»، باسم الموظف وتاريخها ومبلغها كصادر، ورابط إلى سجل السلف حسب الصلاحية.
- الرد النقدي: تصنيف «رد سلفة نقدًا» كوارد للخزينة.
- خصم السلفة من الراتب: تسوية غير نقدية لا تدخل قائمة مصروفات جديدة.
- الإجماليات تعتمد الفلاتر الحالية: التشغيلية، السلف، إجمالي الخارج هنا، والرد النقدي. إجمالي الخارج في هذه الصفحة لا يشمل الرواتب؛ الرواتب محفوظة في قسمها والتقارير.
- إلغاء المصروف العادي يظل موثقًا. صفوف السلف المرتبطة لا تستخدم زر إلغاء المصروف؛ تُراجع من سجلها الأصلي.
- لا تتغير RLS أو صلاحيات الفروع. تظهر البيانات المسموح للحساب بقراءتها؛ عرض بيانات السلف يتطلب صلاحيتها الحالية، ولا يمنح قسم المصروفات وصولًا إضافيًا.

التقارير وDashboard يميزان المصروفات التشغيلية عن السلف. أُضيفت بطاقات السلف المصروفة والرد النقدي وحركة الخزينة للتقرير. السلفة تُخصم مرة واحدة من حركة الخزينة، والراتب يُخصم بمقدار الدفع الفعلي؛ التسوية ليست خروجًا نقديًا جديدًا.

التحقق: 58 اختبار وحدة/SQL/حسابات/مستودع نجحت، وفحص JavaScript والبناء نجحا. نجحت اختبارات الواجهة القائمة الثلاثة واختبار advance-expenses الجديد باستخدام خادم محاكاة فقط. الاختبار الجديد يغطي تسجيل السلفة وظهورها، الرد النقدي، التسوية من الراتب، عدم إنشاء expenses مكررة، الفلاتر والتحديث والتقارير والموبايل. لم تُستخدم بيانات مرضى أو تُكتب حركات على Supabase أثناء الاختبار. لم يُختبر تنزيل OTA على هاتف فعلي في هذه المرحلة.

لإعادة اختبار السيناريو، شغّل npm start ثم:

```
node tests/e2e/advance-expenses.mjs
```
