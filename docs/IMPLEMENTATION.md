- الرئيسية: التحصيل والمصروفات والمستحقات والرواتب والسلف وعدد الحالات، مع فلاتر اليوم والأسبوع (السبت) والشهر والعام والفترة المخصصة، ومقارنة رسومية للحركة النقدية. العدد والأرصدة الحالية موضحة كلقطة حالية.
- الحالات وتفاصيل الحالة: مسلسل تلقائي يبدأ 001، اسم وفرع وتعاقد وتواريخ وحالة وملاحظات؛ تعديل موثق؛ سجل دفعات؛ حالة سداد محسوبة تلقائيًا.
- التحصيل: عدة دفعات مستقلة، مبلغ حتى قرشين، رقم إيصال تلقائي قابل للتعديل، تاريخ ووقت وطريقة ومسجّل وملاحظات. بحث بالحالة والإيصال وفلاتر الفرع والتاريخ والطريقة. منع التحصيل الزائد والإيصال المكرر.
- المصروفات: تصنيفات وقيمة وفرع وتاريخ ووقت وطريقة ومسجّل وملاحظات، بحث وفلاتر. المصروف هنا مدفوع فعليًا، وليس فاتورة مورد غير مسددة.
- الموظفون: إضافة وتعديل وبحث، وظيفة حرة مع اقتراحات، فرع وراتب وتعيين وحالة وملاحظات.
- الرواتب: استحقاق شهري بلقطة من الأساسي وإضافات وخصومات وتسوية سلف؛ مدفوع جزئي ثم سداد الباقي بحركات مستقلة؛ منع راتب مكرر للشهر نفسه وتجاوز صافي المستحق.
- السلف: صرف متعدد، رد نقدي، أو خصم من الراتب؛ رصيد متبقٍ وسجل حركة. الخصم لا ينشئ مصروفًا جديدًا.
- التقارير: تحصيل فعلي وتعاقدات وأرصدة والتزامات رواتب ومصروفات ورواتب وسلف وحركة خزينة. الحركات الملغاة تظل ظاهرة بوسمها وتُستبعد من الإجماليات. XLSX فعلي، وطباعة/حفظ PDF من المتصفح.
- الحسابات والصلاحيات: إنشاء وتعديل وتفعيل وتعطيل ودور وصلاحيات وفروع. في Demo محاكاة مؤقتة فقط، دون حفظ كلمات مرور؛ في التشغيل المتصل عمليات Auth الإدارية عبر Edge Function موثوقة.
- النشاط: المستخدم والوقت والكيان والقيم السابقة والجديدة. في Demo سجل ذاكرة يمكن للمطور تغييره؛ الحماية الحقيقية في SQL عبر صلاحيات وtrigger يمنع التعديل والحذف.
- الإعدادات: تعريف حالة الاتصال والهوية والعملة والفروع وإضافة فرع بواسطة مدير النظام.

## الاختبارات الفعلية

نجحت 14 حالة اختبار في `npm test`، بينها اختبار مركب يشغّل migrations الأربعة على PostgreSQL مضمّن عبر PGlite مع محاكاة `auth.users` و`auth.uid()` وأدوار Supabase. يشمل الدفعات المتعددة والكاملة والمبالغ العشرية والتواريخ غير الصحيحة، منع التكرار وتجاوز الرصيد، الرواتب الجزئية والسلف والصافي، الإلغاء الموثق، رفض تغيير صلاحيات الموظف والكتابة الإدارية المباشرة وحماية Audit.

نجح اختبار متصفح Edge headless على سطح المكتب و390px: منع الدخول غير المربوط، حالة ودفعات جزئية ثم كاملة، رفض الزيادة، موظف وتعديله، سلفتان وراتب جزئي وسداد باقيه، مصروف، إنشاء وتعطيل حساب Demo، وجود أثر النشاط، تنزيل Excel وفحص محتواه، إخراج PDF، التنقل بقائمة الهاتف وعدم تجاوز عرض الشاشة، وبدء اختبار فارغ بعد إعادة التحميل. لا أخطاء JavaScript أثناء المسار.

نجح فحص JavaScript، وفحص TypeScript لوظيفتي Edge باستخدام `deno check --node-modules-dir=none`، وفحص الاعتماديات `npm audit` دون ثغرات معروفة وقت التنفيذ. راجعت صور الواجهة بصريًا، وأصلحت تداخل طبقة القائمة على الهاتف.

ظهرت أثناء التطوير مشكلة في محدد اختبار وصف المصروف، وخطأ تركيب SQL أثناء إضافة الوقت؛ تم إصلاحهما وإعادة الاختبارات. لا توجد حالات فاشلة باقية في الفحوص المذكورة.

## ما لم يُختبر وما يبقى للمرحلة التالية

- لم يُنشأ أو يُربط أو يُنشر أي مشروع Supabase. لا حفظ سحابي أو مشاركة فعلية بين الأجهزة في النسخة الحالية.
- فحص SQL المحلي ليس اختبارًا لخدمات Supabase Auth/PostgREST/SMTP/Edge في بيئتها الحقيقية. يلزم نشر migrations والوظائف واختبار عقود REST والتوكنات وCORS وتحديد المحاولات واستعادة البريد وإدارة الحسابات على المشروع الفعلي.
- يلزم اختبار من جهازين، وتعارض عمليات متزامنة فعليًا، وجلسة حساب معطل، وكل دور وفروعه، وخطة النسخ الاحتياطي قبل إدخال بيانات المركز. المعاملات المالية مؤمنة بقفل ومعاملة في SQL، لكن التزامن الشبكي الحقيقي لم يُجرّب.
- لا يسمح بتغيير فرع حالة أو موظف موجود بمجرد تعديل بياناته، لحماية تصنيف حركاته السابقة. النقل يحتاج إجراء مستقل لاحقًا.
- تصحيح التحصيل والمصروف مدعوم بالإلغاء الموثق وإعادة التسجيل. استحقاقات الرواتب وتسويات السلف المثبتة لا تعدل ولا تحذف من الواجهة؛ تدفقات تصحيحها المتقدمة تحتاج معالجة محاسبية إضافية قبل الاستخدام إذا كانت مطلوبة.
