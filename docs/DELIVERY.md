# حالة التسليم والتحقق

## تسجيل الدخول والاتصال

ثبت من Logs المنشورة أن الفشل كان LOGIN_PROFILE_READ_FAILED، ومن PostgreSQL أنه نقص SELECT على profiles لحساب service_role (SQLSTATE 42501). تجاوز RLS لا يمنح صلاحيات الجدول تلقائيًا. طُبقت migration الجديدة 007_edge_service_permissions.sql: SELECT على profiles وINSERT على audit_logs لإعادة تعيين كلمة المرور، دون منح تعديل/حذف. أكد المستخدم بعدها دخوله الحقيقي إلى Dashboard بنجاح. لم تُعَد migrations القديمة ولم يلزم نشر Function جديدة لهذا الإصلاح.

المشروع المستهدف pgasaphvjavvpqfplfap. الواجهة تستخدم المفتاح العام فقط وAccess Token للمستخدم. الجداول الـ13 الفعلية مفعّل عليها RLS؛ لا SELECT لـ anon ولا كتابة مباشرة للمستخدم authenticated. الصلاحيات والفروع تُطبق في RPC والسياسات. عُطّل التسجيل العام للحسابات، وضُبط عنوان Auth المحلي وCORS للمتصفح وAndroid.

## ما تم اختباره

- 53 اختبارًا محليًا ناجحًا، صفر فشل: SQL، الحسابات، الصلاحيات، سجل التدقيق، Rate Limit، الجلسات وتجديدها، حفظ رقم الهاتف، منع تكرار RPC وتطابق العقود.
- أوامر test:case-payments وtest:ui وtest:supabase-ui نجحت. تستخدم بيانات مصطنعة وخادمًا معترضًا محليًا؛ لا تُثبت عمل API السحابي.
- سيناريو الحالة 30,000، دفعة 10,000 ثم 5,000: المدفوع 15,000 والمتبقي 15,000؛ الدفعتان في التحصيلات والإجماليات، مع اختبار دفع كامل وإلغاء موثّق وتصحيح وموبايل.
- نجح tests/live/transactional-smoke.sql على قاعدة Supabase الفعلية: تعديل حالة مصطنعة، دفعات وتكرار الطلب ومنع الزيادة ومصروف وموظف وراتب وسلفة وتسوية وتدقيق ورفض ترقية مباشرة. اختُبرت الدالة app_command المنشورة داخل معاملة أُلغيَت بالكامل، ولم تُقرأ بيانات مرضى أو تُحفظ حركات اختبار أو تُستهلك أرقام حالات. ليست تجربة حفظ دائم عبر HTTP أو مزامنة جهازين.
- نجحت OPTIONS للوظيفتين من Origin Android https://localhost، ورُفض طلب admin-users غير المصادق عليه بـ401.
- نجح فحص JavaScript وبناء Web. npm audit --omit=dev لم يجد ثغرات في اعتماديات التشغيل. توجد 4 تحذيرات moderate في سلسلة اعتماديات أدوات CLI للتطوير؛ لم يُنفذ downgrade قسري يفسد توافق Capacitor 8.

## السلوك الحالي

لا توجد خيارات Demo أو دخول مؤقت في التطبيق. إنشاء الحالة يفتح تفاصيلها لتسجيل أول دفعة. المبلغ المتفق عليه ليس تحصيلًا؛ الدفعات مستقلة وغير محدودة وتظهر من المصدر نفسه في التحصيلات والتقارير. إلغاء الدفعة يحتفظ بالأصل والسبب والفاعل. لا حذف نهائي للحركات المالية. الحسابات تميز التدفق النقدي والالتزامات والسلف، ولا تسمي التحصيل ربحًا.

كل الوحدات تقرأ app_snapshot وتكتب app_command أو admin-users بحسب نوع العملية. تُحدّث البيانات بعد الحفظ والدخول والتنقل والتحديث اليدوي؛ لا Realtime ولا حفظ أساسي محلي. عند إغلاق التطبيق يلزم تسجيل الدخول مجددًا؛ تظل بيانات المركز على Supabase.

## حدود القبول المتبقية

يلزم اختبار APK المثبت على جهاز Android فعلي: الدخول، حفظ بيانات مأذون بها، ثم قراءتها من جهاز آخر، وصرف/إلغاء حركة واختبار الفروع بحساب محدود وتعطيله من الإدارة. لم يُوصل جهاز Android لهذا البناء، لذلك لا توجد نتيجة اختبار تثبيت أو تشغيل على جهاز فعلي بعد.

أُضيفت مشاركة XLSX عبر Android ونافذة الطباعة الأصلية لحفظ PDF؛ نجاح تجميع Native لا يساوي اختبار نافذة المشاركة والطباعة على الهاتف. روابط إعادة تعيين كلمة المرور ما زالت محلية وتتطلب كمبيوتر الاختبار والخادم يعمل. لم تُنفذ تجربة إرسال البريد أو إعادة التعيين فعليًا. يلزم اعتماد مسار استعادة يمكن للعميل الوصول إليه قبل الاستخدام البعيد الكامل.

لا توجد استضافة عامة حسب اختيار المستخدم. لا OtaKit حاليًا. احتفظ بمفتاح توقيع Android خارج Git وببيانات اعتماده المؤمّنة لاستمرار التحديثات. لا تعتبر النسخة مقبولة نهائيًا قبل إكمال فحص الجهازين والطباعة والاستعادة.
